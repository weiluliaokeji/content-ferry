# 公众号与技术文章模式（去 AIGC 写作模式）

目标是减少模板感、减少 AIGC 特征，不是执行禁用词扫描。先判断词句在当前上下文中是否真的空泛，再决定是否改。本文档用于**从初稿起就避免套路**，而不是写完再逐词替换。

> 本文件的中文禁用短语清单与结构反模式，部分参考自 MIT 许可的开源项目 [说人话 / shuorenhua](https://github.com/MrGeDiao/shuorenhua)（Copyright © 2026 MrGeDiao），并按文渡的公众号写作场景做了适配与精简。

## 场景与强度

阿文写公众号文章属于 `public-writing` 场景，默认按 `standard` 力度：统一语域、改掉工程师表演腔、商业黑话、自媒体流水线语气和 narrator 腔，必要时并句或换主语。

按命中强度分三档，用来判断“要不要处理”，不代表改写力度：

- **Tier 1（默认替换）**：开场套话、空总结、谄媚句、明显黑话、表演性技术腔、身份式夸奖。单独命中通常就处理。
- **Tier 2（同段聚集才是信号）**：高频连接词、渲染性修饰词、某类姿态词在同一段重复出现。单独出现可放行，聚集时保留最贴切的一个、其余改写。
- **Tier 3（全文密度过高才处理）**：`重要 / 关键 / 核心 / 提升 / 优化 / 推动 / 确保` 等常见词，只在全文饱和使用时才替换一部分。

## 优先处理：Tier 1 短语族

下面每族只列代表项，按“问题族”判断，不追求穷举。遇到未收录的新说法，先看它是不是现有模式的同类变体，再决定要不要补。

### 开场和元话术

直接进入事实、问题、经历或作者判断，不要先宣布自己要开始写。但不得虚构一个“具体事件”作为开场。

- `值得注意的是 / 值得一提的是 / 需要指出的是 / 不可否认的是 / 不难发现 / 不容忽视 / 众所周知` → 删掉，或给具体出处。
- `在当今（时代/社会/环境下）/ 随着……的不断发展 / 在这个……的时代` → 删掉，或说清楚发展了什么、具体时间。
- `让我们一起看看 / 接下来我将为你 / 深入探讨 / 具体来说` → 删掉，直接讨论。
- `不得不说 / 诚然 / 更重要的是 / 一句话总结 / 结论先说清楚 / 简单的说` → 删掉，直接给结论。

### 渲染性强调

这些词本身不禁用；当它们没有具体信息支撑、只是把判断抬高时处理，改回“说清楚具体影响了什么 / 给了什么数据”。

- `深刻的 / 深远的 / 不可磨灭的 / 意义重大 / 具有重要意义` → 说清楚具体做了什么、影响了什么。
- `毋庸置疑 / 至关重要 / 举足轻重 / 发挥着关键作用` → 直接说为什么重要、怎么起作用。
- `令人瞩目 / 令人惊叹 / 意义非凡 / 前所未有 / 史无前例 / 颠覆性` → 给对比数据，或说清楚改变了什么；不要空拔高。
- `毫不夸张地说 / 值得深思 / 令人深思 / 引发思考 / 发人深省 / 不禁让人` → 删掉，让内容本身说话。

### 商业 / 互联网黑话

只有在缺少具体动作、纯靠词撑气势时才处理。它们是行业术语、团队稳定用语或准确技术描述时保留。

- `赋能 / 助力` → 帮、让……能。
- `打造 / 构建（用于“打造体系”之类空对象）` → 做、建。
- `抓手 / 闭环 / 颗粒度 / 对齐 / 拉齐 / 沉淀 / 痛点 / 场景化 / 降本增效` → 方法、完整流程、细节程度、统一、积累、问题、按场景、省钱提速。
- `底层逻辑 / 顶层设计 / 体感 / 心智 / 链路 / 触达 / 透传 / 拉通` → 原因、整体规划、感觉、认知、流程、到达、传递、打通。

### 工程师腔 / 调试腔

AI 模仿 SRE / 工程师口吻讲日常事务，把 debug 术语泛化到一切对话。宾语是 `流量 / 请求 / 峰值 / 异常` 且有系统主语和结果时，先不要机械改。

- `稳稳兜住 / 收口 / 收窄 / 根因 / 落盘（泛化使用时）/ 收敛 / 收束 / 锁住 / 压实 / 兜底` → 处理好、收尾、缩小范围、原因、保存、逐步收拢、固定好、落实、保底。
- `接住（用于你/大家/情绪/需求等抽象宾语）/ 稳稳地接住你 / 拆开看 / 对上了 / 坐实了 / 这轮` → 回应、分开说、吻合、确认、这次。
- `说人话就是 / 不躲不藏不绕不逃 / 说穿` → 删掉，直接说。

### 自媒体 / 流水线语气

单独使用是正常网络用语；AI 批量生产时高频堆砌才暴露机器痕迹。作者已有且有真实经历支撑的口语可以保留，不主动塞入“说真的、我跟你说、太离谱了”等口头禅。

- `保姆级 / 硬核 / 干货 / 拆解 / 梳理 / 盘点 / 一文读懂 / 万字长文 / 建议收藏 / 划重点 / 避坑 / 强烈推荐` → 删掉或换成“详细 / 分析 / 整理 / 列举 / 注意”。
- `绝绝子 / 谁懂啊 / 真的会谢 / 姐妹们 / 狠狠（XX 了）` → 删掉，这是 AI 硬凹网感。

### 洞见骨架 / 价值拔高

- `真正的 X 不是……而是…… / 这不仅仅是……更是…… / 最后比拼的是……` → 多数直接说真正成立的判断；若承载边界、反例或风险则保留。
- `你以为……其实…… / 看似……实则……` → 只用于制造顿悟感时直接说有效判断；有真实反差才保留。

### 过渡废话与空总结

- `综上所述 / 总而言之 / 总的来说 / 总体来看 / 由此可见 / 换句话说 / 简而言之 / 归根结底 / 不言而喻 / 可以说 / 由此可以看出` → 删掉，或给结论。
- `在此过程中 / 本质上 / 核心在于 / 关键在于 / 某种程度上 / 从某种意义上说` → 删掉，或说清楚。
- `这说明了 / 真正值得关注的是` → 没有新增信息时删除；承担转场或论证时只压低姿态，保留作用。

### 无源引用

公开写作里尤其像 AI。要么给具体来源，要么删掉权威铺垫。

- `研究表明…… / 数据显示…… / 有专家指出…… / 业内人士认为…… / 据报道……` → 给出具体研究名称 / 数据来源 / 专家 / 媒体和时间；给不出的，删掉铺垫只留原文里本来就成立、不依赖虚构来源的判断。不能补造机构、数据、年份。

### 谄媚 / 元评论

- `好问题！/ 你说得很对 / 这是一个很好的观点 / 让我来为你解释 / 希望这对你有帮助 / 如果你有其他问题 / 好，/ 行，` → 删掉，直接响应。

### 主动出击腔（血压升高类）

- `我已确认 / 我立马开始 / 要不要我…… / 如果你愿意…… / 只要你回复我…… / 你一回复我就…… / 顺手 / 我先……` → 删掉，直接做或等用户提需求。

### 过度接住 / 心理判断腔

- `我就在这里 / 不用向我解释 / 你不是敏感 / 不是想太多 / 你太清醒了 / 这次我懂了，我真的懂了` → 多数删掉姿态层，改回具体回应或具体判断；不要替对方下心理结论，不要硬演“我懂了”。

### 郑重预告 / 身份认证式夸奖

- `我必须很认真地说一句 / 我要讲一个更深一点的东西 / 你问到了问题的核心 / 你的观察力太敏锐了 / 绝对是顶刊作者的素养` → 删掉预告与夸奖层，直接回答或保留对内容的具体评价。

## 结构性反模式（句 / 段层面）

这些不是某个词的问题，而是句子和段落层面的 AI 痕迹。中英文通用，按“模式”处理，不只看字面。

- **二元对比假戏剧**：`不是 X，而是 Y` 制造虚假顿悟。前半句只用于制造顿悟感时直接说有效判断（`管理流程比代码本身更容易出问题`）；承载边界、反例或风险时保留。
- **否定式列举**：`它不是框架，不是库，也不是工具——它是一种思维方式` 绕一圈。直接说（`把它当作一种思维方式，不是一个具体工具`）。
- **戏剧化碎句**：`三年。两个人。一个想法。` 用句子碎片造假力量感。并成完整句（`两个人花了三年把这个想法做成了产品`）。
- **反问式铺垫**：`如果我告诉你，90% 的创业公司都在犯同一个错误呢？` 吊胃口。直接给事实（`90% 的创业公司在定价上犯同一个错误：按成本定价而不是按价值定价`）。
- **虚假主语**：给无生命事物安人类动作（`该框架赋能了开发者社区`）。抽象空泛时改写（`开发者用这个框架能少写 30% 的样板代码`）；技术文档里描述系统行为的非人主语（`网关在超时后返回 504`）合理，不改。
- **被动语态堆砌**：连续被动隐藏执行者（`系统被优化后，性能被显著提升`）。改主动、给执行者和结果（`我们优化了数据库查询，页面加载从 3 秒降到 0.8 秒`）；学术摘要里的常规被动可保留。
- **三件套列举 / 首先…其次…最后…**：AI 偏爱三个一组或机械递进。两个或一个往往更自然；真实步骤、对比表和操作清单必须保留结构。
- **总结式收尾 / 正能量收尾**：每段或全文末尾用“总之 / 综上”重复已说内容，或不管前面说什么最后都上价值、给鸡汤（`让我们拥抱变化，未来可期`）。前面说清楚就删掉，不补口号句。
- **对称填充**：`既要保证速度，又要保证质量；既要创新突破，又要稳定可靠` 硬凑对仗无信息增量。直接说优先级（`速度和质量之间我们优先质量`）。
- **分条列点强迫症 / 加粗滥用**：任何内容都 1.2.3. 分条，或机械给每个要点加粗。简单回复不必列点；真正的步骤、清单、对比表保留。
- **假口语化 / 硬凹网感**：AI 试图接地气时硬塞流行语，反而更假。真人用是随机的，AI 是批量的，别学。
- **调试腔叙事**：把 `兜住 / 落盘 / 根因 / 收口 / 更稳更硬` 泛化到非技术对话。有真实技术对象且能复述“写到哪里、做了什么”时保留；泛化表演时改回大白话。
- **句长均匀**：每句话长度几乎一样、没有呼吸感。长短句交替，节奏来自删冗余和保留重点，不来自统一抛光。
- **标点腔（破折号过密）**：首句破折号起手、单段两处以上 `——`、连续多段都靠破折号承接。看密度和位置，不单个杀；按语义改回冒号、逗号、括号或直接断句，一段最多留一处真正承担插入或递进的。标题连接符、引用原文、全段仅一处且确实承担语气时保留。

## 翻译腔

这些是英文思维直译到中文的痕迹：

- `一个……的……的……` 长定语链 → 拆成短句。
- 连续被动句（`被优化 / 被改进 / 被赋予`）→ 用主动句，不要为被动虚构执行者。
- `基于……` 开头、`通过……来……`、`对于……而言`、`在……方面`、`从……的角度来看` → 多数可删或简化。

## 误杀防护 / 保留项

以下默认优先保留，除非用户明确要求改风格且不损害信息：

- 数字、日期、版本号、比例、单位、范围、比较关系和限定条件；
- 人名、组织、产品、模型、平台、项目名称，以及观点、行为和责任归属；
- 引号内原话、标题、引用、来源、链接与可核查表述；
- Markdown 标题层级、列表、表格、引用、代码围栏、行内代码、图片和链接地址；
- 命令、代码、接口名、字段名、参数、路径、环境变量、日志、报错和状态码；
- 作者已有的第一人称经历、态度、犹豫、边界和 `【待核查】` 标记；
- 技术文里的系统主语、步骤、清单和术语是信息结构，不因“像 AI”就改成口语或故事；
- 系统行为主语（`网关返回 504`、`缓存过期`）合理，不要机械改。

如果自然度与准确性冲突，优先准确。不要为了“像人”把文本改得更假。

## 正向标准

- 优先呈现原文已有的主体、动作、条件和结果；
- 有判断，但判断来自原文事实和作者态度，不靠拔高；
- 句子长短可以变化，但不强造碎句、金句、反问或戏剧性停顿；
- 允许自然重复，尤其是承担强调、转场和时间推进的重复；
- 只保留原文已有的第一人称和个性，不替作者“注入灵魂”；
- 保持语域一致，不把技术文章改成聊天，不把个人文章改成公告。
