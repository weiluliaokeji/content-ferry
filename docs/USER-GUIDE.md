# 文渡（ContentFerry）用户使用说明

> 适用版本：0.1.x 开发预览版
> 最后更新：2026-09-29

文渡是一款运行在 Windows 本机的 AI 自媒体工作台。它帮助你从主题和资料开始创作文章，在本地 Markdown 文章库中编辑和保存（默认兼容 VitePress，也支持普通 Markdown 内容源），通过 AIGC 特征检测与人工预览后发布到微信公众号。

这份文档既是完整使用说明，也是后续生成网页帮助和 PDF 手册的源文件。界面仍在开发，个别按钮名称可能略有变化。

## 1. 开始前准备

第一次开始使用时，只需要：

- 一台 Windows 10/11 电脑。

首次启动向导会引导你选择数据目录和 AI 服务；进入应用后，再到"归档库"选择本地文章库。

需要发布到微信公众号时，再按本说明第 5～8 节依次添加账号、获取 AppID/AppSecret、配置 IP 白名单和回调地址。只体验本地创作时，可以暂不连接微信公众号。

## 2. 首次启动

安装版直接运行“文渡”。首次启动向导会引导你：

1. 选择数据目录；
2. 初始化 AI 服务；
3. 检查基础环境；
4. 完成设置并重启应用。

普通用户不需要安装 Node.js、Codex CLI、Docker、WSL 或 Hermes Agent。选择 OpenAI Codex 时，安装包会携带所需的内部运行组件；ChatGPT OAuth 登录用于取得模型授权。

### 数据保存在哪里

- 文章正文和文章图片：保存在你选择的本地 Markdown 文章库，默认使用 VitePress 目录结构。
- 账号配置、发布记录、AI 会话、记忆摘要和运行日志：保存在首次启动时选择的文渡数据目录。
- AppSecret、API Key 和 OAuth 凭据：使用 Windows 安全存储保护，不以明文显示或写入日志。

建议把文章库和数据目录纳入自己的备份方案。不要把登录 Cookie 复制到其他电脑，恢复后重新登录更安全。

## 3. 配置 AI 服务

进入“技能与模型”，先配置一个文本模型。模型连接决定由谁执行，技能决定如何执行，两者不是同一件事。

### OpenAI Codex

1. 选择 OpenAI Codex。
2. 点击“使用 ChatGPT OAuth 授权”。
3. 在打开的授权页面完成登录。
4. 返回文渡，等待状态变为可用。

它不要求用户另行安装 Codex 软件，也不依赖 Hermes Agent。

资料卡统一使用应用的 Tavily / Brave / Bing RSS / DuckDuckGo 检索与正文提取链，确保每张自动卡都能保存实际提取的内容快照和来源 URL；模型连接不会绕过这条证据规则。资料卡只是已有参考：写作和评审发现新的事实或实操缺口时，仍应继续补研或在授权范围内实践。稳定的概念解释可由阿文直接说明；当前版本、命令参数、官方要求等易变内容需要核对来源；本机结果和亲身经历只根据作者记录或本篇实践观察，不会由模型推断。只有影响读者判断的具体事实缺口才会标为待核查。

### 其他模型

除预置的 OpenAI Codex 外，文渡支持添加任意 **OpenAI 兼容端点**作为自定义连接：在“技能与模型”填写显示名称、模型名、服务地址（baseUrl）、访问凭证与（可选的）代理地址，即可接入 OpenAI API、OpenRouter、Nous Research、NVIDIA Build、GitHub Copilot 等任意兼容服务。不同提供商所需字段不同（有的要 API Key，有的要模型名或专属服务地址），凭据只加密保存在本机、不会回显或写入日志。每个连接的“代理地址”只影响该连接本身；留空就是直连，文章联网调研也不会借用其他模型连接的代理。

“目标完成核验”是单独的文本技能，负责检查阿文工具任务是否真的完成，不执行工具。默认跟随阿文模型；如果希望执行与核验由不同模型负责，可在“技能与模型”中单独为“目标完成核验”选择模型连接。停用该技能或核验模型不可用时，文渡会保留候选结果并标记未完成，不会绕过核验标记成功。

图片模型与文本模型分开配置。封面提示词技能负责分析文章并生成提示词，图片模型只接收用户最终确认的提示词；除非提示词明确要求，否则不应生成标题文字。

### 联网检索（可选）

GitHub 公共仓库的文件页面若暂时无法抓取，文渡会尝试读取同一文件的官方 Raw 正文；资料来源仍指向原页面。两种地址都无法读取时会显示失败原因，不会把搜索摘要当成已核对正文。

阿文指定某个网站范围检索时，会过滤其他网站的误匹配结果。正文独立评审若因搜索服务故障无法完成额外核验，会保留已经发现的问题和候选稿，并说明哪一步没有完成；不会把候选稿标成通过。

在“技能与模型”页面的“联网检索服务”中可配置 Tavily。它不是大模型，也不需要分配给某一项技能；阿文在补充公开资料时会优先使用它。点击“配置”后填写 Tavily API Key，可先“测试连接”再保存。Key 加密保存在本机、不会回显或写入运行日志；移除后会依次尝试 Brave、Bing RSS 和 DuckDuckGo 等免配置搜索源。

### 阿文专属工作区

在“技能与模型”页面的“阿文专属工作区”中选择一个专用目录并保存。文渡会把阿文自动创建的 Git staging 放在该目录下的 `git-sources/` 子目录中；保存工作区即表示文渡可以在该目录内读写，越出目录的目标会被拒绝。授权按钮和完整参数只在右侧“执行活动”显示一张授权卡，底部阿文对话只显示等待状态并提供跳转入口。

右侧“执行活动”中的“展开查看”会打开同一工作流的浮窗，方便查看完整时间线、参数、工具结果和回传内容；浮窗只是放大视图，不会新增另一套授权入口。

### 图片初审模型（图片找图功能的准备项）

在同一页面的“图片初审模型”中，可以选择关闭 AI 初审、跟随当前阿文模型，或指定一个模型连接。该设置复用已有模型连接和凭据，不需要另填图片服务 Key。OpenAI Codex 当前可用于图片输入；ModelScope、Agnes 等当前图片连接用于生图而不是图片理解，不能选择为初审模型；自定义连接会显示“图片输入待验证”。没有可用视觉模型时，后续找图流程仍会保留规则筛选结果，不会把失败伪装成初审成功。

打开文章编辑器左侧的“图片素材”，点击“打开联网找图”进入宽版找图面板，再输入图片主题搜索 Tavily 候选。每次搜索完成后，搜索词、时间、服务、候选图和初审结果都会按当前文章保存；点击“查看搜图历史”可以重新打开最近 30 次搜索的候选。每张候选图都会显示缩略图、说明和来源页；点击图片可打开大图预览，并可打开原图。若 Tavily 返回了源网页，还会显示“打开源网页”；如果没有返回，文渡不会根据图片地址猜测网页，只会提示“源网页未返回”。若已配置 Codex 视觉初审，文渡会先临时下载候选图并显示“初审通过”“需要人工判断”或“不建议”等提示，初审结束后临时文件会清理。结果只是候选，不会自动下载或修改正文。确认后点击“确认下载并插入推荐位置”，文渡会用现有安全下载器把图片保存到当前文章的 `assets/` 目录；阿文找图时会根据候选说明和文章段落推荐插入前/后的位置，锚点失效时回退到文章末尾，图片前后保留空行。若地址不可访问、不是受支持格式、超过 15 MB 或指向私有网络，文渡会拒绝保存；初审失败时仍保留候选供你人工判断。

在正文底部与阿文对话时，阿文可以按需调用文渡的受控工具：公开网页检索、系统工具发现和文章库只读会在权限范围内自动连续执行；工具发现会动态扫描 PATH 与 Portable 文渡相邻工具目录，可按命令名查询；扫描只看入口文件名，不运行未知程序探测版本。发现到命令不代表阿文有权运行它，实际调用仍须经过本次任务的影响说明和授权；结果会回填给阿文并显示在会话记录和右侧“执行活动”中。阿文会把目标拆成可检查的完成条件，并在每次工具调用后核对结果是否真的回答了目标；退出码为 0、工具显示完成或返回了内容，都不能替代这个核对。若本机结果为空或范围不符，阿文会判断是否存在安全且能回答问题的另一种方法，例如查阅公开来源；公开资料会明确标作远程信息，不能当作本机状态。最终答复还会经过单独的目标核验：证据支持目标时才标为“目标已核验”；如果证据不足，会标为“未完成 · 结论待核查”，保留答复并等待你的指示；五分钟没有收到指示后，正文才会带待核查标记继续。若你选择“只重试上次失败的步骤”，有明确失败或无有效输出的工具调用时，文渡只会重试该调用；若上次停在完成核验阶段，且已有候选答复和工具观察，阿文可只用这些已保存内容修复答复并重新核验，不会运行新工具。若已有观察不足，会说明具体缺口并等待你决定是否采用新方法；没有可复用的观察时，会说明没有原步骤可重试。若模型重复提出的调用已被运行时拦截，阿文会明确告知该调用没有执行以及拦截原因，不会把它说成工具失败或再次重放。点击“起草正文”后，阿文会先判断是否值得实践；若没有帮助，会直接起草，不会让你填写或执行实践清单。只有阿文实际请求代码或网页实践时，执行活动才显示“实践中”；没有实践结果时会显示“阿文判断无需实践，正在准备正文”，只有记录到实际结果后才显示“实践已完成”；需要短代码验证时，可调用 Python 或 Node.js 示例运行。文渡会显示验证目标和本机运行影响；确认后，代码只写入本次实践的临时文件夹。此功能在 Windows 本机运行，不能强制断网或完全隔离；代码运行或写入项目文件时，授权卡会说明本次操作的影响，并按本次操作或本次任务范围授权，不会自动安装缺少的工具，也不会套用旧的文章级或项目级授权。已完成的实践结果会作为有条件的观察提供给正文生成。在正文编辑时，你也可以告诉阿文要验证什么；阿文会把结果整理成普通段落建议供你确认。拒绝建议会保留实践结果但不写入正文。阿文还可以预览本次任务生成的本地 HTML Demo 并截图；预览限制在当前任务临时目录，禁用外网请求、下载、弹窗和系统权限，截图存入文章 assets 并附可分享的来源说明。阿文还可以读取公开 HTTPS 页面，并在同一站点使用可见的 GET 搜索、筛选和翻页链接；按需要截取本次网页窗口，截图保存在文章 `assets/`，由阿文判断是否放入草稿。遇到登录或验证码时，可在实践窗口中手动处理；SSO 登录会在人工接管期间打开同一临时隔离会话中的 HTTPS 弹窗。完成后返回最初授权的网站，打开“网页实践”菜单并选择“我已完成并返回原网站，继续只读验证”；弹窗会关闭，窗口恢复同站只读访问。弹窗仅在人工接管时可用，下载、危险提交和非认证 POST 仍会被拦截。工具权限由文渡按目标和副作用判断，不由模型返回内容决定。工作流事件、请求元数据、工具结果和快照会保存在本机；即使工作流失败，也会保留已执行调用的审计。重启后会按任务状态提供恢复或重规划入口，不会默默重放不确定的调用。如果关联工作流已终止失败、不完整或取消，重新进入时会显示原因并等待你处理，不会继续显示为正在判断或尝试恢复已结束的工作流。 正文独立评审每完成一轮，执行活动都会保存该轮意见摘要和候选版本指纹；修订稿也会立即保存为续审检查点。重启后会从最新候选重新核验，不会从更早版本继续。你也可以直接对阿文说“找一张操作界面截图”“给这篇文章找配图”等，阿文会调用联网找图工具，按当前文章保存候选和历史，并自动打开图片候选面板；它不会在你确认前下载图片或修改正文。

同一条对话请求遇到网络重试时，文渡会复用原执行和最终答复，避免重复追加回复。授权通过后，对话会显示当前执行或重新判断状态；如果工作流失败，会显示可重试的失败状态。右侧活动面板也会持续刷新步骤和核验结果，不会一直显示旧的授权状态。核验未通过后，阿文会先判断现有观察能否支持修订；若需要新信息，会选择与已失败方法不同的安全途径，若没有可行方法则说明具体阻塞。完全相同的已成功工具调用会被拦截；连续两次核验仍指出相同未满足要求且没有新观察或作者指示时，工作流默认停止并保留未完成原因。若已有可用观察且答复有实质修订，阿文会额外进行一次基于原观察的最终核验，不重跑工具；仍未通过时会停止并保留具体缺口。改写答复不会重置无进展计数。阿文会按本轮最新问题选择查询范围；例如“在本机”优先查本机已安装清单，询问“可安装的软件”才查软件源目录。接受阿文建议后，正文先进入当前草稿，点击“保存文章”后才会记录为已应用并保存；若文章保存成功但建议处理记录同步失败，顶栏会显示“正文已保存，建议状态待同步”，再次点击“保存文章”可重试同步。

当公开搜索页要求登录或人机验证时，文渡会打开“联网检索协助”窗口并保留该站点会话。请在窗口中自行完成网站要求的操作，再回到资料窗口点击“完成验证后重试”。文渡不会代替用户解验证码或绕过网站验证。

阿文自主实践的进度、授权与结果统一显示在右侧“执行活动”。默认视图使用通俗进度和影响说明；目录、参数、工具回传和原始事件按需展开。熟练用户可以在活动详情中查看可用的排查操作；此前左侧“代码与工具”手动面板已移除。Git 源码分析等其他执行工具是否可用，取决于本次文章流程和右侧活动中实际显示的能力；不要沿用旧面板中的目录授权或运行目标说明。

本机命令由阿文按文章目标选择：你只需描述要验证什么，无需填写命令、参数或工作目录。阿文可以调用 Windows 已能找到的命令行工具，也会扫描与便携版相邻的工具目录。工具发现按命令名动态查询，不需要为每款软件登记或重新打包；扫描只检查入口文件名，不运行程序探测版本。文渡按常见命令动词识别只读查询、写入、安装、删除和外部提交，无法判断的操作按写入处理；只读命令也需要本次任务授权。授权按当前任务中的工具和操作范围生效；同一范围内只改变查询参数时，文渡会重新评估风险并可继续使用本任务授权，若工具、操作类别或影响范围变化则重新请求授权。文渡会说明它将运行什么、可能影响什么，并请求本次任务授权。工具使用当前 Windows 用户权限，文章任务临时目录不是安全沙箱；授权前可展开查看参数。通用入口不接受命令解释器、整段 shell 文本或可执行文件路径。若找不到软件，执行活动会显示原因；可先确认它已安装并可在本机终端按名称运行。

执行期间，聊天、正文起草编辑区与右侧“执行活动”会显示简短阶段、当前操作、工具结果摘要和目标核验状态；不会显示模型私有推理原文。断线后会从已保存的活动事件继续展示。每轮候选答复和核验理由、证据核对会保存在本机工作流记录中，供执行活动回看；普通运行日志不写入完整文章或模型请求，完整模型调用审计仅在你主动开启后保存。只有阿文要把目标标为已完成时，核验引文才必须能在本轮请求或工具观察中找到；首次引文无法定位时，文渡会基于同一候选和观察额外核验一次，不重新生成答复或重放工具。若引文修正仍失败，阿文会在有限预算内再尝试一次基于原始观察修答或选择不同取证方式，不重跑已完成的工具；仍失败就以“待核查”结束，不标记成功。停止原因会区分“核验器没给引文”“引文无法对应本轮来源”和“来源引文有效但仍不能满足目标”。前两种属于核验依据问题，不代表本机命令没有返回观察；可在“执行活动”中查看证据核对记录。若核验确认当前无法完成，系统会保留“未完成”结论和具体原因。若连续两次核验仍指出相同未满足要求，期间又没有新工具观察或作者要求，阿文默认停止并保留候选答复和具体未通过原因。若已有可用工具观察且答复有实质修订，会额外做一次基于原观察的最终核验，不重复运行工具；仍未通过时会停止并保留具体缺口。改写答复不会重置无进展计数。Windows 命令通过真实终端会话运行，以兼容 nvm 等需要控制台的程序；权限仍按文渡展示的本次目标和范围判断。退出码为 0、空输出、无匹配或工具状态显示完成，都不能单独证明目标已达成。若某调用没有提供可用观察，阿文应尝试安全且实质不同的方法；完全相同的无进展调用会被运行时拦截并要求重新规划。单个命令达到自身执行期限会显示为失败，阿文可在原授权范围内重新判断后续步骤；实践任务本身没有自动总时限，可以手动停止。

完成核验记录会为作者请求和每条工具观察附上 `request-1`、`tool-1` 等来源编号。阿文引用时必须同时给出来源编号和其中的连续原文；文渡会核对引文是否确实来自指定记录，并在执行活动中保留可定位和未定位的数量。编号用于让你更容易找到核验依据，不能代替原文证据。

如果连续两次后续操作都没有拿到新信息，阿文会停止并在聊天里说明已经取得什么、卡在哪个具体步骤、还缺什么证据，以及可以怎样继续；之前成功的结果不会丢掉，文章中的相关结论会按待核查处理。任务仍运行时，你补充新方向会重新开始无进展计数，避免把新方案和旧方案的失败连在一起。你明确要求把本机命令结果作为配图时，阿文可从本轮成功命令的实际输出生成带说明的展示图，并建议放在相关段落。图片不是 Windows 终端窗口截图；若输出看起来包含凭据或本机绝对路径，文渡会拒绝生成图片，避免把敏感信息放进文章素材。

如果你明确要求阿文本轮在本机执行命令并给出结果，阿文会尝试调用当前可用的工具，不会用旧会话结果代替本轮执行。一次筛选或搜索没有匹配项时，这只说明该筛选结果为空；阿文会在当前授权范围内尝试完整列表或其他能核对目标的观察方式，并说明统计口径。Windows 上 PATH 中的 PowerShell 脚本也可作为已安装工具发现；发现过程不会运行脚本。

文渡桌面版联网调研默认沿用 Windows 系统网络设置，包括系统代理和 PAC/WPAD。若系统代理仍无法访问公开搜索源，可在“联网检索服务”中单独设置“检索代理”（例如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080`）覆盖调研路线。该代理**只用于联网检索**，与“其他模型”里各连接的代理相互独立、互不影响；无效地址会被忽略并回退到 Windows 系统网络路线。

## 4. 配置本地文章库

进入"归档库"，在配置窗口选择“VitePress 文章库”或“普通 Markdown 文章库”。VitePress 选择 `docs` 目录而不是只选择 `docs/posts`；普通 Markdown 文章库选择包含多个 `<文章目录>/index.md` 的目录，不会套用 `posts/` 或 `public/` 约定。

例如：

```text
D:\Workbench\weiluliaokejiBlogs\docs
```

选择 `docs` 后，文渡才能同时识别站点结构、文章目录、Front Matter、图片路径和排序规则。扫描时会排除 `index.md`、排序说明等站点页面，保留真正的文章。

文渡以本地 Markdown 文件为正式正文来源：

- 新建草稿会直接写入文章库；
- 从文章库扫描出来的文章可以继续编辑和发布；
- 可以同时使用 Obsidian 或其他 Markdown 工具编辑；
- 标题、日期、`publish`、`tags` 等现有 Front Matter 字段应被保留；
- 图片通常保存在文章目录的 `assets` 中。

外部工具修改文件后，回到文渡重新扫描或打开文章，以磁盘上的最新内容为准。

所见即所得编辑时，段落之间的空行不会另存为 `<br />` 标签。若旧文章已经含有独立的 `<br />`，可切换到“Markdown 原文”模式检查并按需删除；文渡不会自动清除原文件中已有的 HTML。

## 5. 添加微信公众号账号

进入“账号”，添加平台为“微信公众号”的账号。账号名称只是文渡中的显示名称，可以与公众号名称一致，也可以使用便于区分的备注。

建议先填写账号定位：

- 账号定位；
- 目标读者；
- 禁用话题；
- 写作风格；
- 常用栏目。

起草正文时，阿文会从当前工作空间文章库中找最多 3 篇主题相关的旧文，并把少量摘录、标题和文章库相对路径作为观点与术语参考。文章库可能包含不同账号的稿件，因此阿文不会据此推断当前账号风格，也不会声称它们是同一作者的旧观点；旧文不自动作为当前事实依据，也不会为了引用而硬套。

在“账号”页面可以为单个账号打开“代表文章样本”，文章按创建时间从新到旧排列，也可以按创建日期起止范围筛选（包含起止日期当天）。创建时间优先取文章 Front Matter 的 `created` 字段；缺少该字段时使用文件创建时间。带该账号发布记录的文章会显示发布依据；没有发布记录的文章只有在你明确确认属于该账号且已完成后才可选入。VitePress 文章的 `publish: false` 表示尚未发布，仍会作为待确认候选显示；只有明确标记为 `draft` 的文章和当前未完成文章不能作为样本。归档文章照常显示和选择，不作区别处理。

保存至少两篇代表文章后，可以点击“提炼风格档案”。阿文只分析已保存且明确归属此账号的文章，最多使用 12 篇；它会分别总结账号共同风格、有样本支持的体裁特点和正文配图习惯。提炼结果先作为待审核候选保存，你可以修改、拒绝或确认启用；只有确认才会建立新版本，旧版本及其样本来源会保留。启用档案后，也可以在当前版本旁点击“手工编辑”，修改共同风格、配图习惯和体裁特点；保存会立即建立并启用一个新版本，沿用当前版本的样本来源，旧版本仍可查看。该档案独立于账号定位中手动填写的写作风格，提炼、确认和手工编辑都不会覆盖手动内容。

生成或修改提纲、起草主稿时，阿文会结合文章目标账号的手动写作风格和已确认档案，按本篇主题选择适用的表达和结构特点；档案也可记录样本中明确可见的正文配图习惯，本篇明确要求优先。没有目标账号或尚无已确认档案时，不会套用其他账号的档案。正文起草前，阿文会生成简短的风格选择说明；这项说明生成失败时，仍会把已确认档案交给正文模型参考，并提示采用默认档案。起草完成后，编辑器会把风格选择说明、配图处理结果和正文评审状态分开展示。账号配图习惯只是选择参考，不是每篇文章都必须配图；没有实践截图也不代表文章有缺陷，若通用图片能帮助读者理解正文，阿文仍会搜索并插入。正文生成后，阿文会结合主题、配图习惯、已存在的实践截图和正文内容判断是否需要联网配图；需要时自动搜索、筛选和插入到合适段落，图下会保留来源链接，不逐张向你确认。若候选没通过相关性初审、来源或插入位置不可靠、或服务不可用，就跳过配图，不影响正文。来源链接不代表图片使用授权已经核实；发布前仍按普通文章审核检查图片使用条件。模型生成结果仍需作者审核。渠道稿的账号档案应用仍在开发中。

## 6. 获取微信公众号 AppID 和 AppSecret

后台菜单可能随版本调整。当前常见路径如下：

1. 打开 [微信开发者平台](https://developers.weixin.qq.com/platform) 并登录。
2. 点击页面左上角“我的业务与服务”。
3. 选择“公众号”。
4. 在“基础信息”区域查看 AppID。
5. 按后台要求完成管理员验证后生成或重置 AppSecret。
6. 立即把 AppSecret 保存到密码管理器，再填入文渡。

AppSecret 通常只在生成或重置时完整显示。重置后，使用旧 AppSecret 的程序会失效；修改后应在文渡中重新“保存并测试连接”。

### 在文渡中保存并测试

1. 在“账号”找到目标公众号。
2. 点击“连接微信”或“编辑凭证”。
3. 填入 AppID、AppSecret 和回调 Token。
4. 点击“保存并测试连接”。

文渡会向微信申请一次 `access_token`，用来同时验证 AppID、AppSecret、网络连通性和 IP 白名单。测试失败时窗口不应静默关闭，应显示微信返回的错误原因。

## 7. 配置 IP 白名单

微信公众号 API 只接受白名单内公网 IP 发起的请求。家庭宽带或动态网络的出口 IP 变化后，需要重新更新。

常见操作路径同上面AppID、AppSecret 获取操作的步骤

填写的是公网出口 IP，不是 `127.0.0.1`，也不是通常以 `192.168.*`、`10.*` 开头的局域网地址。如果使用代理、公司网络、云函数或隧道，请确认微信实际看到的出口 IP。

## 8. 配置微信回调

微信接口返回“任务提交成功”并不等于文章最终发布成功。原创声明失败、平台审核或其他原因仍可能导致失败，因此文渡需要通过回调接收最终结果。

文渡本地回调路径为：

```text
/wechat/callback/<账号 ID>
```

本地服务监听 `127.0.0.1:4317`，微信公众号无法直接访问本机地址。需要使用可公网访问的 HTTPS 地址，将请求安全转发到这一本地路径。常见配置位置同上面AppID、AppSecret 获取操作的步骤，为“基本信息” → “域名与消息推送配置”。

配置时注意：

- URL 使用公网 HTTPS 地址，不能填写 `127.0.0.1`；
- Token 必须与文渡中该账号填写的回调 Token 一致；
- 当前明文模式只适合已确认的开发阶段能力；启用其他加密模式前应核对实现状态；
- 不要把 EncodingAESKey 误填到 Token 输入框；
- 公网转发只开放必要的回调路径，不要把整个本地服务暴露到互联网。


## 9. 从主题开始创作

在工作台点击“新建文章”，可在同一个窗口一次输入：

- 一个主题；
- 一个可选标题（也可以稍后由阿文推荐）；
- 自己的观点或零散想法；
- 已有资料和需要保留的事实；
- 必须处理的网页链接（“指定资料链接”，每行一条）；
- 文章希望解决的问题。

“创作主题或想法”可直接粘贴较长的构思和资料（最多 12000 字符），它决定文章讨论什么；“写作目标”描述希望读者得到什么，两者不应混用。主题是唯一必填项；未填写目标读者、写作目标或核心角度时，阿文会从主题与账号定位推断合理、具体的读者任务，并让提纲和正文保持聚焦；这只用于确定创作范围，不会推断作者经历或事实。如果没有填写标题且输入较长，文渡会先创建一个临时草稿标题；后续可在“编辑创作方向”中让阿文推荐或自行修改正式标题。

如果当前只绑定了一个账号，文渡会默认选中它；绑定多个账号时需要自行选择，仍可暂不选择。

账号定位与主题一致时，AI 不会重复询问账号已经保存的信息。只有文章明显偏离定位，或缺少会影响事实与核心角度的必要信息时，才会补问。

推荐流程（选择“创建并联网补研”时）：

1. 整理创作简报；
2. 阿文默认联网补充资料，优先检索官方文档与原始资料；
3. 查看研究结论和资料卡，取消勾选不希望用于写作的来源；
4. AI 基于已选资料形成提纲，独立评审会先核对整份提纲是否兑现创作简报要求的文章类型、范围和读者结果，再逐节核对读者问题、章节作用和内容方向；复杂指南不能只列宽泛标题，提纲要点直接写读者将获得的答案、判断或操作方向，不以“说明、提醒、给出”等作者待办代替内容，也不能把核心章节整段推给读者自行查官网或文档；尚待核对的事实可留给正文补研，提纲不要求先提供证据；提纲也不限制正文继续展开；
5. AI 起草正文；
6. 在编辑器中继续修改；

提交新建表单前可在“创建后如何开始”中选择“创建并联网补研”或“仅创建草稿，稍后补资料”。默认联网补研会创建 VitePress 草稿、内容项目和创作简报，然后打开联网资料窗口。选择仅创建草稿时，文渡只在本地创建文章、项目、简报和待处理的指定资料链接，不调用模型，也不访问这些链接；之后回到工作台，你可以直接点击“直接编辑正文”开始写作，也可以主动选择“生成提纲”或“联网补研”。直接编辑无需先通过 AI 生成提纲。调研深度有快速核实、均衡调研或深入研究三档，只控制本轮检索预算，不代表资料数量或研究质量。联网补研以研究计划中的未覆盖维度决定是否继续，预算耗尽时会保留缺口并标记为部分调研。之后如需调整创作主题或想法、目标、读者、角度、资料或标题，可在工作台选择“编辑创作方向”。已有资料的文章会同时显示“查看资料”和“继续补研”，前者打开已有资料卡，后者打开同一资料窗口并自动定位到补研输入区。资料卡的作者决定会用选中状态明确显示；已采纳、待核验和已拒绝均可再次切换。创作主题会作为后续补研、提纲和标题推荐的上下文，和正式文章标题分开保存；保存修改后的标题才会同步更新 VitePress 文件和文章目录。简报保存后不会覆盖已经确认的提纲版本。

阿文一次最多推荐三个标题，会直接使用当前尚未保存的简报内容；如果本地文章库中存在可识别的系列标题，例如“零成本基建系列——”，会显示本次用于推荐的历史系列。文渡只会在当前方向相关时建议延续该系列，最终标题始终由你决定。

如果生成提纲时出现“本地连接被中断”，通常表示文渡正在重启或开发环境刚重新编译完成。等待窗口稳定后重新点击“生成提纲”即可；已经流式显示的内容会保留在窗口中，可继续编辑后保存。

阿文推荐的标题只是候选，不会自动替换当前标题。点击某一候选标题（或自行修改标题）后再保存简报，文渡才会同步更新文章的 Front Matter、一级标题和对应目录。

保存创作简报后，点击“联网补研”。阿文会按文章主题、核心角度和未解决的问题规划查询；“写一篇公众号文章”等原始创作措辞用于理解范围，不会作为搜索主题整句复制。搜索结果只用于发现候选网页；系统会提取网页正文后才允许生成自动资料卡。每张卡显示直接来源、摘要、关键主张、为什么值得看、质量/时效判断、证据边界，以及短正文摘录、提取时间和 SHA-256 内容指纹；相同主张的同质来源会合并，卡片数量不设产品固定值。未能提取正文的候选不会伪造成资料卡。同一项目内，带跟踪参数、片段、默认端口或尾部斜杠差异的同一来源会自动合并。在卡片上选择“采纳”“待核验”或“拒绝”：已采纳资料进入提纲和正式事实依据；推荐但已核对正文的资料只可支持待作者确认的候选正文。若卡片聚合不准确，可在“资料卡纠错”中拆分来源或合并同一主张，来源和作者决定都会保留；正文不会自动插入脚注、外链或归因文字。对需要登录、验证码或复杂网页交互的来源，当前版本不会伪造结果，应由你自行核对。

生成正文时，阿文会把已采纳资料卡中的具体事实、做法、评价、限制或反例按提纲章节落地，并遵守卡片的质量、时效和证据边界；不会只把提纲改写成泛泛段落。若所有正文小节仍与提纲内容相同（仅列表等格式发生变化），系统会把它当作尚未展开的提纲，要求正常修订流程补成读者可读的正文；不使用固定字数门槛。正文会基于完整提纲连贯起草；支持流式生成的模型会边生成边显示，不支持流式输出时会改用普通生成并在完成后显示，系统定期保存候选检查点。生成中断时保留已收到的内容并标明未完成，不进入配图和整篇评审；完整初稿生成后再统一配图和独立评审。已抓取并核对网页正文的推荐资料也可支持候选正文中的具体表述，这些表述会在编辑器标为“待作者确认”，左侧“资料来源”显示原网页、支持摘录和确认/拒绝操作。改动对应段落后需要重新核对；未提取正文的搜索摘要及手工摘录不会以此方式进入。资料卡仍不会自动变成正文中的 URL、脚注或资料列表。资料卡只是当前可用的参考，不是写作资料的上限：起草前会检查提纲承诺是否缺少网页依据，只有必要时才先补研；正文评审发现资料卡之外仍缺当前事实时，会尝试继续补研、核对网页正文、修订相关段落并再次评审。补研会把已尝试查询和结果带入下一轮，阻止没有新结果的重复搜索；如果找不到有价值的新路线，阿文会停止并列出未解决的缺口，不会把“停止搜索”说成“资料已充分”。如果评审还指出不依赖该证据的文字问题，阿文会继续修好这些部分；证据缺口仍会保留为未解决，不会因此通过。评审发现需要本篇实际观察时，会按当前任务授权开展实践；取得新观察后仅修订受影响段落并重新评审。补研没有新依据、授权被拒、实践失败或没有新观察时会保留候选稿和具体原因。评审还会逐项对照提纲承诺，并检查评审引用的正文原句是否确实存在；遗漏或无法定位的承诺不能通过。应用重启后的候选自动续审仍在开发。

新增的网页正文或实践观察有时只是在核实原句，不需要改字；阿文仍会带着新证据重新评审一次。若同一问题依旧没有解决，会保留候选稿和具体缺口，不会反复做相同的查询。

评审还会核对文章是否真正完成标题、目标和提纲承诺的读者任务。例如指南若缺少关键步骤，仅写“请去官网查看”，阿文应指出缺口并尝试补齐有正文依据的资料；只有本篇确实需要实际操作结果时才会申请实践。调研计划中旧的缺口会重新核对，不会不加判断地变成正文问题。

调研计划若留下明确缺口，阿文会在新起草前先判断它是否仍妨碍文章完成读者任务；确有必要才尝试一次联网补研。补研失败时仍可保留候选正文，但关键缺口会显示为待处理，不能因为评审遗漏而显示“已通过”。起草前的实践评估若失败，会保留错误原因并继续写作；失败本身不会自动阻止通过。正文独立评审会检查是否有必须由本篇实践支撑、但正文尚未兑现的承诺，有才会要求补实践。

多章节正文进入评审修订后，阿文会优先只替换受意见影响、能在当前候选中准确定位的文字，保留其他章节。若修改位置不明确、跨越多个章节或会改掉已确认标题，系统会保留当前候选并显示原因；修订后仍由独立评审检查，不会因局部替换就自动视为事实已核实。

资料工作台会先显示本次要回答的问题、所需证据维度、时效和冲突提醒、已经收集到的材料以及仍有缺口。若预算耗尽或缺少某项证据，结果会明确显示为“部分调研”；请直接以缺口为提示继续补研，或手工核验和补录资料，系统不会把它写成已充分完成。

在正文编辑器左侧“资料来源”中，可以针对选中文本、当前段落或整篇文章发起临时调研。临时结果会显示实际范围、抓取时间和易变信息复核提醒，只在本次编辑会话保留；它不会自动改写正文、插入链接或成为正式资料。资料来源也会显示已保存证据及其采纳状态。若要使用临时摘录或改写建议，请先在当前正文中选中目标文字，再明确替换该选区；也可保存为“待核验证据”。保存后仍需单独采纳，才会用于提纲和正文生成。离开编辑器或重启应用后，未保存的临时结果会清除。

“指定资料链接”与普通笔记分开保存。系统会自动逐条抓取正文并尝试生成资料卡：成功时显示“已获取”；资料卡单独选择“采纳”后进入提纲和正式事实依据，未采纳但正文已核对的推荐资料仅可进入待确认候选正文。抓取失败时显示失败原因，可打开来源、重试补研或使用“手工补录资料卡”。只有需要登录、验证码、复杂网页交互或内容出现冲突时，才需要人工介入。进行中状态会显示已耗时和最近进度；超过 45 秒没有新进度时会提示可能在等待来源响应，可暂停或停止本轮补研。

如果资料还不够，在“第三步：补充资料”底部的“继续补研”中直接告诉阿文还要查什么，例如“核查当前调用限额，只使用官方文档”或“补充不适用场景和反例”。原有资料不会被覆盖，新结论和不重复的新资料会追加；这轮要求与结论也会保存在本文的“与阿文对话”记录中，之后编辑正文时可以回看。需要更新会变化的信息时，点击工具栏中的“时效刷新”：它优先复核产品能力、价格、规则、版本、限额和适用条件，不会删除背景材料或改变你的采纳决定。工具栏中的“调研运行历史”可查看每次初始调研、继续补研和时效刷新当时的计划、结论、资料快照与决定；失败、取消或暂停的运行也会保留原始要求、错误和检查点，失败或取消记录可点击“沿用原请求重试”，无需重新填写补研信息；如果不再需要处理，可点击“移除记录”，它只从历史列表隐藏，不删除资料卡、结论或审计事件。三个辅助工具共用页面内面板，一次只展开一个，不会遮挡资料卡。补研较慢时可在进度区点击“暂停补研”，系统会让当前联网请求完成但暂不写入资料卡，并保存结果检查点；之后用“继续补研”即可从检查点写入，不会重复整轮检索。也可点击“停止补研”取消。已经保存的资料卡和历史运行会保留，未完成的本轮不会伪装成成功。若应用在补研期间重启，重新打开资料窗口会自动接管仍在排队或心跳过期的任务，完成后刷新资料卡。第三步底部的「进入提纲」按钮会随状态变化：提纲已确认时显示「编辑提纲」、有未确认草稿时显示「继续编辑提纲草稿」、都没有时显示「用已选资料生成提纲」。提纲已确认后点它只打开已确认内容，不会重新生成，也不会自动吸收本次新采纳的资料；要让新资料进入提纲，请使用下方的「按已选资料重新生成提纲」。若已经生成过提纲，第三步底部还会出现「按已选资料重新生成提纲」：点击后先提示确认，再按当前已采纳资料重新生成；重新生成在你确认新提纲前不会覆盖原提纲，生成后可在提纲编辑器点「恢复原提纲（重新生成前）」撤销。同一区域还提供「修改标题」，可随时更改文章标题或让阿文推荐候选，保存后会同步更新文章列表、目录与已发布草稿中的标题；若提纲已生成，提纲内的一级标题可在打开提纲后单独调整。

如果你已经查到一段可靠资料，也可以在同一窗口的“手工补录资料卡”中填写标题、摘要、关键结论和可选链接。保存后资料卡会默认纳入后续提纲和正文；没有链接的卡片会保留为手工资料，方便继续追溯。若该链接与指定资料相同，系统会将该手工摘要记录为该指定资料的核验结果。

阿文生成提纲后会先进行独立评审，最多自动修订五轮；评审会检查读者目标、章节推进、每节的信息增量、资料覆盖和账号风格，并核对提纲主线是否兑现作者要求的文章类型和读者结果，避免相邻子问题取代主要目标；对于指南、教程和实践主题，还会核对关键决策、操作与结果判断是否有清楚的章节承载位置，但不会强制套用固定章节模板。各节可按内容需要用一句话概括，也可分组展开多个场景、步骤或命令，不要求统一的要点数量。提纲阶段尚未取得实际实践结果本身不会阻断提纲；适合实测的文章可以先安排正常的章节标题和验证目标，实际观察留到正文起草阶段。事实、目标或结构问题，以及影响读者理解的可执行改进，都会进入修订并在每轮后重新评审。只有没有遗留意见时才显示通过；五轮后仍有意见会保留候选和具体原因，供你处理或重新评审。纯属个人偏好的可选润色不会阻断提纲。评审可使用当前任务允许的公开网页搜索，但检索结果不会自动成为正式资料或正文。评审规则可在“技能与模型 → 文章独立评审”中查看和修改，也可为评审单独选择模型。评审默认跟随撰写模型；这是独立评审调用，但同一模型可能存在判断偏差。需要增加模型视角差异时，可在“技能与模型 → 文章独立评审”中为评审指定另一条模型连接。你修改提纲后，页面会标记原评审记录已过期；仍可继续编辑和确认，也可以重新评审。评审详情默认收起，展开后可看修订说明和逐条依据。

生成主稿后，阿文会先做独立评审，再把结果交给你。评审会对照提纲、已采纳资料、实践观察和正文中的事实与限制；需要核对时可在当前任务授权范围内搜索公开网页，但搜索结果只作为评审证据，不会自动加入文章。事实风险和影响读者使用的实质缺口会进入最多三轮自动修订；每轮后重新评审，只有没有遗留意见才显示通过。仍未解决的问题会保留在评审详情中，由你处理。评审状态收在窗口顶部的状态栏里，点击可查看具体意见和依据，不占正文编辑空间。编辑正文后，原评审记录会标记为“对应旧版本”，不影响继续写作。

选择 AI 改写生成 CSDN、博客园、掘金或 51CTO 渠道稿时，也会由独立评审检查源文章观点、平台适配、事实边界和账号禁区；可执行的实质改进同样会进入最多三轮自动修订。选择“直接使用主稿”时不会重复评审。评审摘要默认收起，展开可查看具体意见；编辑后会标记为对应旧版本。评审期间的联网结果不会自动变成渠道稿的事实依据；渠道稿仍需你按普通文章流程审核和确认。

确认提纲后，工作台仍会提供“编辑提纲”。提纲只展示文章的章节、判断和论证角度，不应混入检索任务、待核查清单或给作者的写作指令。编辑到一半可以点击“保存提纲草稿”，再次打开时会继续上次保存的版本；弹窗滚动时，底部操作栏仍会显示保存入口。保存草稿不会把项目标记为“提纲已就绪”，其中的标题修改也只保留在草稿中。只有点击“确认提纲并标记为已就绪”后，项目才会进入“提纲已就绪”并允许起草正文，同时正式同步文章标题、Front Matter 和目录；“放弃本次修改”会关闭编辑器且不保存本次修改。提纲编辑器下方的“和阿文一起优化”分为“优化提纲结构”和“优化文章标题”：结构模式按逐行差异展示新增、删除和改动附近的上下文，标题模式返回多个候选标题。建议不会自动覆盖当前内容；应用前若原提纲又发生变化，系统会提示重新生成建议，避免覆盖新修改。点击标题候选后只更新当前编辑内容，并同步提纲一级标题。标题候选不会自动替换文章，也不会默认重新联网检索。应用结构建议或重新生成提纲后，编辑器底部会出现「撤销上次应用」或「恢复原提纲（重新生成前）」；若建议依赖尚未确认的事实，请回到资料调研工作台补研。

文章简报中的“正文篇幅”可选精简、标准、详细或交给阿文判断；未明确指定时，阿文会依据写作目标、目标读者和提纲承诺决定详略。一项承诺若包含多个判断、操作步骤或条件，会分别讲清；简单说明保持精炼，复杂任务充分展开。指南与实践内容按需说明前提、操作、结果判断和边界；概念与观点文章围绕解释和论据展开，不强行套用教程结构，也不按标题分配固定字数。已确认提纲是正文必须覆盖的内容，不限制正文展开程度；阿文可以在保留范围和二级章节标题的前提下补充有助于读者理解或行动的解释、例子、步骤和小节，新增事实仍须有可靠依据。阿文会按读者任务选择真正有用的资料卡，不会为覆盖资料卡而逐张罗列；资料卡不足以支撑关键事实或实践结论时，仍会通过补研或获授权实践补齐。正文独立评审会区分补充资料、获授权实践、正文修订和作者范围决定；纯文字修订不会被用来伪造缺失的证据。若模型明确报告正文输出触及长度上限，文渡会提高输出预算重试一次；再次触顶会说明正文未完整生成，不会把它送去评审。起草的规划、实践、配图筛选、评审和停止原因会按顺序保存在本篇任务记录中，重新打开文章时可查看历史；重启不会自动重放工具操作。

### 回看文章的创作过程

如果起草已生成候选正文，但你还没有点击“保存文章”就关闭或离开，重新打开项目会先恢复这份候选正文，并显示未保存状态及上次的活动记录；打开动作不会重做实践或联网。提纲或正式文章后来修改过、旧任务缺少文章基准时会提示你核对，此时不能自动沿旧目标续审。恢复本身不会重新评审，也不会把旧评审改成通过；两者都未变化时可主动点击“从候选继续评审”，阿文会重新读取当前资料和实践记录、评审该候选，并按新发现的缺口继续处理，不重复生成初稿或下载配图。

如果正文评审要求本篇实测，而你决定本文不再提供该实测，可在评审下方填写新的文章范围：写清本文改为提供什么、哪些实测承诺不再保留，然后点击“按新范围修订并复审”。阿文会据此改候选正文和必要的标题，再请独立评审重新检查；这不会产生虚构的实测结果，也不会把旧评审改成通过。若你改过正文，或提纲、正式文章在上次任务后已变化，请先核对当前内容；范围调整入口只对未过期的相应候选评审开放。
你选择“带缺口继续起草”后，阿文不会在同一轮评审里立刻重做刚跳过的实践；缺口会留在评审中。你仍可另行提出新的验证目标，或明确调整本文范围。

文章发布完成并归档后，创作过程不会丢失。「归档库」每篇文章右侧的渠道条按已添加的平台显示分发状态；显示“未生成”时可直接点击加号生成渠道稿，已有渠道稿可点击进入继续编辑。点击文章右侧的 ⋯ 展开操作区，除「重新发布」外，还会按这篇文章实际留下的记录显示「查看创作方向」「查看素材」「查看提纲」，可随时回看当时的创作简报、联网资料卡和提纲。同一时刻只会展开一行，点击其他文章的 ⋯ 会自动收起上一行。

不是通过文渡创建的文章（例如你用其他编辑器直接写进文章库的）没有这些记录，展开后只会显示「重新发布」。

点「重新发布」会打开这篇文章并定位到右侧「发布设置」。这里的「发布账号」决定发布去向，切换账号后配置项随之切换：

- 选**微信公众号**：显示微信留言、申请原创声明、开启赞赏、加入合集等微信专属选项，顶栏按钮为「准备发布」。
- 选 **CSDN / 博客园 / 掘金 / 51CTO**：面板会提示「在 XX 渠道稿中发布」，顶栏按钮变为「进入 XX 渠道稿」。这些平台的栏目、分类、标签、发布形式等平台专属设置都在渠道稿里填写；这里保存的作者、摘要和封面会带到渠道稿。

## 10. 编辑文章

编辑器支持“所见即所得”和“Markdown 原文”两种模式。切换模式时会尽量保持顶部可见内容一致。所见即所得模式的结构化工具栏会在编辑交互停止约 1.8 秒后自动淡出；将鼠标移到工具栏原来的顶部区域、点击、聚焦或输入时会重新显示，滚动正文不会唤回工具栏，正文区域内普通的鼠标移动也不会打断阅读。选中文字时，浮动工具栏提供行内代码、代码块转换和高亮操作；顶部工具栏也提供行内代码和代码块转换按钮，代码块与行内代码按钮按相同顺序相邻排列。代码块转换后再次点击会转回普通段落。

编辑器左上角的返回按钮会标明并返回打开文章前所在的页面：从工作台打开时返回工作台，从归档库打开时返回归档库；新建正文草稿返回工作台。

常用操作：

- `Ctrl+S`：保存；
- `Ctrl+Z`：撤销；
- `Ctrl+Y`：重做；
- 拖入、粘贴或选择本地图片；
- 插入标题、列表、任务列表、链接、引用、代码和表格；
- 点击文章结构中的标题跳转到对应段落；
- 手机预览微信公众号中的大致阅读效果；
- `Ctrl+Shift+H`：给选中的文字加高亮（Obsidian 风格的 `==文本==`）。

离开存在未保存修改的文章时，文渡应提示保存或放弃，避免内容丢失。

### 高亮（`==文本==`）

在所见即所得模式中选中文字后，点击浮动工具栏或文章顶部工具栏的荧光笔按钮即可加上黄色背景高亮；也可以在正文里用 `==` 把要强调的文字包起来，和 Obsidian 的用法一致：

```
这是 ==重点== 内容
```

要点：

- `==` 必须紧贴文字。`a == b == c` 这类写法不会被当成高亮。
- 高亮里可以再套强调或链接，例如 `==**重点**==`。
- 代码块和行内代码里的 `==` 保持原样，不会被高亮。
- 在所见即所得模式下高亮直接显示为黄底；保存回文件后仍是 `==文本==`，来回切换不会丢失。

发布到各平台时，文渡会按平台能力自动转换，你看到的效果保持一致：微信公众号会用带背景色的样式（它的编辑器会剥掉语义标签），其余平台用标准高亮标签，CSDN 直接使用原生的 `==` 语法。

### mermaid 图表

在正文里用 ```mermaid 代码块写图表，编辑时就会直接显示成图，和 Obsidian 一样：

    ```mermaid
    graph TD
      A[开始] --> B[结束]
    ```

要点：

- **点一下图**就切回源码可以修改，把光标移到别处又会自动变回图。
- 图形还没写完（语法不完整）时会临时显示成代码块，写完就自动变回图；如果语法有误，代码块下方会说明原因。
- 存回文件的始终是 ```mermaid 代码块本身，不会变成图片，方便你继续用其它 Markdown 工具编辑。
- 发布到微信、CSDN、博客园、掘金和 51CTO 时，图表同样会转成图片上传，读者不必依赖平台支持 mermaid。

### 代码块的行号和高亮

编辑文章和手机预览里，普通代码块会带行号，并按语言给关键字、字符串、注释、数字等着色，长行可以左右滑动查看，不会撑破版面：

    ```js
    const a = 1; // 注释
    ```

要点：

- 这只是显示效果：存回文件的仍是原来的 ```js 代码块，行号不会被保存，复制代码也不会带出行号。
- 发布到各平台时，代码块样式由平台决定，与编辑器里的着色无关。

### 正文里的图表和代码在发布时如何处理

发布到微信、CSDN、博客园、掘金和 51CTO 时，正文会先按平台能力转换，转换发生在上传之前：

- ```` ```mermaid ```` 代码块会先在本地渲染成 PNG 图片，再和正文图片一起上传，读者在手机上直接看到图，不要求平台支持 mermaid。流程图、时序图、类图等 mermaid 支持的语法都适用。
- 其它语言的代码块会转成各平台的代码样式。微信公众号只识别自己的代码块样式，因此不论原文标注的是什么语言，都会按等宽字体、灰底的代码块呈现。
- 图表渲染失败时不会丢失内容：文渡保留原始代码块，并在运行日志中记录 `mermaid 渲染失败` 及原因。可在“运行日志”里搜索该关键字定位不被支持的语法。

## 11. 使用阿文和选区 AI

“阿文”是文章顾问。它以当前文章、当前文章的历史会话和提炼后的写作记忆为上下文，可以讨论选题、结构、表达、读者理解成本和发布准备。

选中正文后可使用：

- 去 AI 味；
- 改写；
- 扩写；
- 缩写；
- 补充案例；
- AIGC 特征检测。

未选中文字时，AIGC 特征检测会检测当前正文全文，按钮显示“检测全文内容”；选中一段文字后，按钮会改为“检测选中内容”，只将该段发送给腾讯朱雀或 ContentAny。只有全文检测结果会保存到本篇文章的质量记录；之后打开“准备发布”会直接显示已完成的检测，无需重复检测。选区检测仅用于局部优化，不会替代全文检测。

选择动作后，可以在“补充要求（可选）”中说明本次改写意图，例如“保留技术术语，语气更直接”或“面向非技术读者解释，不要营销化表达”。留空时使用技能默认规则；按 `Ctrl+Enter` 可直接生成替换建议。

AI 修改先以建议形式展示。建议卡会贴在对应正文段落之后，可拖动到更顺手的位置；切换编辑模式后仍会回到该段落。每条建议会明确标注“替换原文”“追加到原文后”或“插入到原文前”：只有替换建议会改掉原文，追加/前置建议会以独立段落插入并保留原文。建议中的 replacement 必须是可以直接写入文章的正文内容，分析反馈和修改理由不会作为“接受追加”的内容。阿文对话中的待处理建议提供“定位”按钮，点击后正文编辑区会滚动到对应原文片段并短暂高亮。同一段落可以有多个互斥的替换或追加方案，接受其中一个后其他方案会自动拒绝。接受后会先更新当前编辑草稿，并显示“已应用到当前草稿，尚未保存”；点击“保存文章”成功后才会显示“已应用并保存”。接受后可以继续润色已插入或已替换的文字，保存不会因为建议文本不再与原建议完全一致而让建议重新出现。保存失败可以重试，离开文章时如果有未保存的建议应用，文渡会让你选择保存并返回、放弃本次修改或继续编辑。放弃后建议会恢复为待处理；拒绝不会修改文章。正文不会重复显示已保存处理的建议，但阿文会话会保留完整建议内容、操作类型、原文和建议文本及“已应用并保存”“已拒绝”或“无法定位”的处理记录。如果历史会话中仍有对应当前正文、但尚未处理的建议，继续提问前会提示数量；你可以选择“批量拒绝并继续”“保留建议，继续提问”或“取消发送”，已应用到未保存草稿的建议不会被批量拒绝。发送给阿文的消息会先显示“正在发送”；若模型或网络中断，消息会保留并标出失败，可在原消息旁点击“↻ 重新发送”，不会无提示消失。历史会话中最后一条没有阿文回复的用户消息，也会显示为可重发。重要、稳定且可复用的写作偏好会被摘要，而不是把整段会话直接当作长期记忆。正文底部的“与阿文讨论本文”面板中，“管理本文记忆”“收起”和“发送”共用右侧输入区底部的紧凑操作行，顶部不再单独预留按钮高度；点击管理可查看待确认候选、启用或删除当前文章的记忆。弹窗把备份恢复和删除操作分开，删除派生记忆不会删除文章正文，也可以导出 JSON 备份并合并导入。

长文章中的图片会优先保证编辑器和首屏内容可交互；首屏外图片采用懒加载和异步解码。SVG 图表会在本地后台转换并缓存，重复打开文章不会重复进行耗时转换，加载期间也不会锁住正文滚动。

## 12. 技能与模型

技能决定任务规则，模型连接决定执行服务。

应用版本号可在「技能与模型」页面底部的「关于文渡」中查看。打包版在版本号后显示打包时间，例如 `0.2.3-20260927T123456Z`（UTC）；反馈问题时请一并提供该完整标识，运行日志也会记录它。Portable 包应运行完整的 EXE，不要只复制 `win-unpacked` 目录里的 `文渡.exe`。

在文章右侧点击“查看授权与执行活动”后，会立即打开执行窗口。若授权记录还在读取，请稍候；如果显示读取失败，可点“重新读取”。阿文发现不到专用任务时仍可在授权后尝试已安装软件的通用命令；如果软件不在桌面进程能发现的位置，执行活动会说明本轮实际阻碍。反馈这类问题时，请附“关于文渡”的完整版本标识和执行活动中的错误说明。

内置技能包括：

- 微信公众号文章撰写；
- 平台稿改写；
- 选区 AI 编辑；
- 文章选区去 AI 味；
- 文章摘要生成；
- 封面提示词生成；
- 文章封面生成；
- 腾讯朱雀 AI 检测；
- ContentAny AI 检测；
- 阿文文章顾问。

每个技能拥有独立 `SKILL.md`，部分技能还有 `references/`。修改技能会影响后续调用结果；不熟悉提示词和输出约束时，建议先备份再改。

同类技能默认按大模型类型分组（文本类、图像类、无模型）。要成批更换某类技能使用的模型连接：

1. 在分组标题右侧点「全选」，勾选该组下全部技能（或逐一点击技能卡片右上角的勾选框）；点「取消全选」可清空。
2. 在「选择目标模型…」下拉里挑一个已配置的模型连接。
3. 点「应用到选中的 N 个技能」，所选技能会一次性切换到该连接。

「全选 / 取消全选」仅出现在有模型连接的分组（文本类、图像类）；「无模型技能」走浏览器自动化，没有可切换的大模型。

## 13. 封面和摘要

封面可以来自：

- 本地图片；
- 文章中的图片；
- 微信素材库；
- AI 生成。

本地图片确认后会复制到文章对应素材目录。裁剪封面时通过可视矩形框选择区域，不需要填写微信 `media_id`。裁剪比例跟随提示词中明确写出的宽高比；未写比例时，微信公众号封面默认使用 2.35:1。

使用 AI 生成封面时，ModelScope 和 Agnes 会按提示词里的比例选择最接近的生图画幅；裁剪工具按提示词中的比例输出。比如提示词写“2.35:1”，封面不会再固定生成 16:9 或正方形；提示词未写比例时，微信公众号封面默认按 2.35:1 处理。

使用 AI 生成封面时：

1. 先让“封面提示词生成”技能根据正文产生可编辑提示词；
2. 用户检查并修改提示词；
3. 图片模型只接收最终提示词；
4. 默认不生成标题、Logo、水印或二维码；
5. 只有提示词明确要求文字时才允许生成文字。

图片模型排队时间不固定。生成期间可继续编辑正文和文章设置；文渡会持续等待，直到图片服务明确成功或失败。若开启“AI 调用审计”，可在审计日志中查看本次图片任务的提交、轮询和下载响应摘要。

封面提示词属于文章发布设置：点击“保存发布设置”后会与封面、摘要和作者一起保存；下次进入文章会自动带回。生成图片期间仍可点击“保存文章”保存正文修改。

微信公众号摘要最多 120 字。摘要技能会主动留出字数余量，并要求完整收尾；若模型仍返回过长或未收尾的摘要，会重试一次，再按完整句、分句或词语边界安全收尾，避免直接切在半句话中。点击「AI 生成适配摘要」时只会锁定这个按钮，等待模型返回期间仍可滚动、编辑正文和保存文章；生成结果返回后会写入当前摘要输入框，保存文章后才会持久化。

## 14. AIGC 特征检测

腾讯朱雀和 ContentAny 都通过浏览器自动化运行，不需要大模型连接。

通常文渡会自动：

1. 打开检测网页；
2. 填入待检测内容；
3. 点击检测；
4. 等待结果；
5. 提取分段样式、比例或参考结论并回填。

只有登录、验证码、额度用尽或网页结构变化时才需要人工接管。检测结果是文章优化信号，不是事实判定。即使 AI 特征较高，用户仍可填写理由后例外发布。

## 15. 发布到微信公众号

微信公众号草稿是官方接口的必经步骤：

1. 文渡上传正文图片和封面；
2. 调用 `draft/add` 创建微信草稿；
3. 若文章设置中选择了“申请原创声明”“开启赞赏”或“加入合集”，在发布记录点击“在微信后台完善并发布”。文渡会打开可见浏览器，定位到对应草稿卡片并尝试悬停、点击卡片的“编辑”按钮；能可靠识别的选项会自动尝试设置；
4. 用户在微信后台人工预览，确认原创、赞赏、合集等设置并点击发布；
5. 或回到文渡选择普通发布或群发；
6. 等待微信最终回执。

“普通发布”和“群发”不同：

- 普通发布使用 `freepublish/submit`，适合获得永久链接等场景，不等于向所有关注者推送；
- 群发使用 `message/mass/sendall`，会消耗公众号群发额度；
- 接口 `errcode=0` 只表示任务提交成功，不表示最终发布成功。

原创、快捷转载、创作来源、赞赏等能力是否能由接口直接设置，以微信当前开放能力为准。文章设置可保存“文章由 AI 生成”“申请原创声明”“开启赞赏”和已有合集名称；勾选“文章由 AI 生成”表示用户确认发布来源，创建草稿时这些设置会固定到该发布任务。需要网页处理时，在发布记录点击“在微信后台完善并发布”，文渡会尝试在微信编辑器中选择“内容由AI生成”。处理合集时，文渡会从微信的“选择合集”窗口读取当前可见的名称，并按已选公众号缓存；下次编辑同一公众号的文章时可直接从下拉建议中选择，旁边会显示最近同步时间。缓存只用于方便选择，微信后台仍是最终来源；页面变化或额外确认会保留给你处理，最后的预览和发布始终由你完成。申请原创声明与开启赞赏默认勾选，作者默认填入最近使用过的账号；从工作台点击微信公众号的“设置并发布”时，未设置过发布账号的文章会自动选中第一个已绑定的微信公众号账号，仍可自行切换；这些设置均可在文章设置中随时修改。

点击“微信草稿箱”后，如果尚未登录，先自行选择扫码或账号密码登录；文渡不会替你点击登录按钮或改变登录方式。登录成功后会自动进入“内容管理 → 草稿箱”，用于手机预览和处理微信后台设置。

如果回调未及时到达，但已经在微信编辑器中确认最终结果，可以在发布记录人工校正为已发布、失败或取消发布，并填写简短原因。

## 16. CSDN 渠道稿（当前可用范围）

在"账号"添加 CSDN 账号后，账号行显示“发布时检查登录”。CSDN 登录态保存在文渡的持久浏览器会话中，无需单独填写 Cookie 或密码；发布时会自动检查，失效时再按窗口提示登录。之后进入"工作台"，在文章右侧点击"生成 CSDN 稿"（已归档文章在"归档库"点 ⋯ 展开后点"重新发布"，在发布设置里选 CSDN 账号即可进入 CSDN 渠道稿）。生成方式默认是“直接使用主稿”；如需平台化改写，可手动改选 AI 改写。创建后会打开一个与主稿同款的独立工作台（顶栏 + 左侧工具 + 中间所见即所得编辑器 + 右侧手机预览/发布设置），只是发布渠道不同：

- 左侧工具：正文（字数/图片数/阅读时长）、文章结构（点击跳转到对应标题）、图片素材（列出正文图片）。
- 中间编辑器：与主稿完全相同的所见即所得编辑器，支持图片、列表、表格等；源稿图片（含 VitePress 源文章的相对路径图片）也能正常预览，新插入的图片独立存到该渠道稿的资产目录。
- 右侧面板有三个标签页：「AI 助手」「手机预览」「发布设置」。
  - **AI 助手**：选中正文后可让 AI 去 AI 味、改写、扩写、缩写或补充案例（先预览再「应用替换」，不会自动覆盖原文）；未选中时下达指令会对整篇生效。处理产生的对话会记录下来。
  - **手机预览**：按 CSDN 调性实时预览。
  - **发布设置**：填写作者、摘要与封面。摘要默认沿用主稿摘要，可点「AI 生成适配摘要」重写；封面默认沿用主稿封面，可「选择本地图片」上传，也可在「AI 生成封面」里选图片模型、让 AI 根据正文生成提示词再生成并设为封面。
- 编辑器工具栏同样提供「所见即所得 / Markdown 原文」切换：点击 `</>` 进入 Markdown 源码编辑，再点 `✎` 切回。冻结后的稿只读，不能切换或直接编辑。
- 工作台（未归档文章）每条文章按“标题与右对齐时间 → 状态与发布账号 → 渠道状态条 → 文章操作”分层展示分发状态；状态文案统一说明下一步，例如“资料已补充，可生成提纲或继续补研”“文章主稿已生成，可继续编辑或发布到其他平台”。导入文章的状态提示为“文章正文可编辑，也可发布到其他平台”，不再使用容易产生来源歧义的“外部文章”前缀。渠道状态条用平台图标 + 状态图标表示（鼠标悬停显示平台与状态文字），允许在窄窗口换行，彻底区分主稿与渠道稿。文章操作集中在底部工具栏，普通按钮采用紧凑统一样式，删除草稿使用同规格的危险按钮：状态如「未发布 / 草稿待发布 / 已发布 / 未生成 / 草稿 / 已冻结」，操作为「设置并发布 / 继续发布 / 进入 CSDN 稿 / 生成 CSDN 稿」等对应按钮。未来新增渠道会自动追加，不会挤压文章标题。左侧导航顶部的箭头可收缩或展开侧边栏；收缩后保留放大的图标入口，悬停可查看名称。
- 重进已生成的稿：CSDN 行显示「草稿 / 已冻结」状态，点“进入 CSDN 稿”直接打开工作台；若该文章存在多份渠道稿（不同账号），会先弹选择框让你挑一份或“新建渠道稿”。新建入口仍是“生成 CSDN 稿”。
- CSDN 稿与主稿、微信公众号稿互不覆盖；在草稿态点击顶栏「发布到 CSDN」即可一步完成：自动保存未存修改 → 冻结为内容快照（弹窗提示锁定后只能重新生成）→ 创建本地可恢复发布任务，并自动进入「发布记录」查看进度。已处于冻结（approved）态的稿直接创建任务，不再有独立的「审核并冻结」或「创建 CSDN 发布任务」按钮。不再需要的渠道稿可点「删除渠道稿」移除。
- CSDN 一期不允许公众号原文链接、正文引用、文末延伸阅读、二维码、评论区引流或其他软引流内容；发现这类内容时不能冻结。
- 冻结后任务不会立即向 CSDN 提交。随后在发布设置面板或「发布记录」的 CSDN 任务区，点击「确认并发布到 CSDN」：这一步是该次发布的最终确认，文渡会在后台复用按账号隔离且持久保留登录态的 CSDN 会话，上传素材、填充发布选项并提交，成功后自动读取文章链接。文章标签默认从主稿 Front Matter 的 `tags` 读取，最多填入 5 个；封面上传后会完成 CSDN 的裁剪确认，并核对封面预览。账号没有可选的分类专栏时会留空继续，因为当前 CSDN 表单未将其标记为必填。登录失效、标签或封面无法可靠填入、页面异常时才会打开窗口供你接管；若最终发布按钮未点击，任务会提示尚未提交，你检查窗口后可重新确认；已经提交但读不到链接时会安全降级为「待人工核对」，你可在 CSDN 后台核实后用「校正状态」标记。文渡不会在回读不确定时谎报发布成功，也不会自动重试已提交任务。
- 若任务停在「浏览器填充中」，说明 CSDN 尚未收到最终提交；可在「发布记录」或渠道稿工作台点「重新准备 CSDN 发布」。文渡会忽略同一任务正在运行时的重复点击；任务进入「正在读取 CSDN 回执」后不再提供重试入口。
- 提示：后台自动化依赖 CSDN 编辑器页面结构。若页面变化或账号需要重新登录，窗口会显示具体状态；登录后回到文渡重新点击「登录 CSDN 后继续」。读回不确定时请先到 CSDN 后台核实，再校正文渡记录。

## 17. 博客园渠道稿（当前可用范围）

博客园使用官方 MetaWeblog 接口（API Key 方式）直发文章，不需要浏览器自动化。

**第一步：添加博客园账号**

1. 登录博客园，进入「后台 → 设置 → 其它设置 → MetaWeblog 访问令牌」，复制你的 API Key（形如一串随机字符，与登录密码不同）。
2. 在文渡「账号」中点击添加，选择「博客园」，填写你的博客园用户名（形如 `weiluliaokeji`，即博客地址 `https://www.cnblogs.com/用户名` 中的用户名）和刚才复制的 API Key。
3. 保存后文渡会加密保存凭据，不会在界面回显；发布时凭据缺失或错误会进入「待补凭据」状态，可回到账号设置修正。

**第二步：生成并编辑博客园稿**

在「工作台」中打开一篇文章，点击右侧「生成博客园稿」（已归档文章先在「归档库」点 ⋯ 展开后点「重新发布」回到工作台），选择目标账号与生成方式（默认直接使用主稿，也可改选 AI 改写）。进入渠道稿前会先保存主稿当前编辑内容；直接使用主稿也会检查公众号引流，若拦截会显示具体命中的文字。检查针对实际引流链接或引导语，普通的「延伸阅读」标题和一般性文字提及不会单独触发拦截。会打开与 CSDN 同款的独立工作台：左侧工具、中间所见即所得编辑器、右侧「AI 助手 / 手机预览 / 发布设置」三栏。编辑完成后点「保存渠道稿」，确认无误后点「审核并冻结」。博客园稿不允许公众号原文链接、文末引流链接、二维码或其他软引流内容。

在“发布设置”中，点击“读取博客园个人分类与 Tag”会打开博客园创作后台，并从该窗口当前登录账号读取“个人分类”和自定义 Tag 供选择；首次使用请先在打开的窗口登录。博客园没有公开的这两类列表接口，因此不会把 MetaWeblog 返回的网站分类误当成个人分类。两处都保留手工输入。

**第三步：两段式发布**

1. 冻结后点击「创建博客园发布任务」：文渡先把冻结快照和任务以“排队”状态保存到本地，再由主进程任务运行器异步通过 MetaWeblog 调用 `newPost` 创建博客园草稿，并把正文中的本地图片上传到博客园图床、封面作为正文第一张图、自动加入 `[Markdown]` 分类。创建任务后可以先离开当前页面，回来查看任务状态。
2. 草稿创建成功后，任务状态显示「草稿待公开」并展示博客园草稿链接。你可以先点开链接检查标题、正文、图片与分类。
3. 确认无误后点击「确认公开」：文渡调用 `editPost` 把草稿公开，完成后展示正式文章链接，任务状态变为「已发布」。不确认则不会公开，重复点击也不会产生重复文章。

同一冻结版本只会保留一个可恢复的活动任务；已发布、已取消或结果待核对的任务不会被普通重试覆盖。删除本地渠道稿只会从渠道稿列表隐藏，发布记录和事件仍保留，方便追溯。

**第四步：异常与人工校正**

- 凭据缺失或错误：任务进入「待补凭据」，补齐账号 API Key 后可继续。
- 网络失败或公开失败：任务显示失败原因，可在网络恢复后重试。
- 结果不确定（如超时但博客园实际已发布）：任务进入「待人工核对」，你可在博客园后台核实后用「校正状态」把任务标记为已发布、失败或取消，避免重复发布。

## 18. 掘金渠道稿（当前可用范围）

掘金使用 `content_api` 接口纯 API 直发，不需要浏览器自动化；正文中的本地图片会自动上传到掘金 ImageX 图床并替换为 CDN 链接，远程图片保持外链。

**第一步：添加掘金账号**

1. 在文渡「账号」中点击添加，选择「掘金」，填写账号名称并保存。
2. 保存后点击该账号的「配置掘金凭据」，配置 Cookie、AID、UUID 三项：
   - **推荐：自动获取 Cookie**：点击「自动获取 Cookie」，文渡会弹出掘金登录窗口（登录为掘金原生流程，请扫码或使用手机号验证码登录）。检测到登录成功后，文渡会自动抓取 Cookie 串、AID（默认 2608）和 UUID 并回填保存，随后关闭登录窗口；抓取后会用掘金接口自动验证，验证未通过时凭据仍会保存，但界面会提示你检查登录态。
   - 手动配置：登录掘金后从浏览器开发者工具复制请求 Cookie（含 `sessionid`），粘贴到 Cookie 输入框；AID 默认 2608，UUID 可留空。
3. 凭据由文渡加密保存，不会在界面回显；发布时凭据缺失或错误会进入「待补凭据」状态，可回到账号设置修正。

**第二步：生成并编辑掘金稿**

在「工作台」中打开一篇文章，点击右侧「生成掘金稿」（已归档文章先在「归档库」点 ⋯ 展开后点「重新发布」回到工作台），选择目标账号与生成方式（默认直接使用主稿，也可改选 AI 改写）。直接使用主稿时会先快速打开渠道稿，分类和标签先按确定性规则填充；更贴合正文的 AI 标签推荐在后台完成，不会阻塞进入编辑器。会打开与 CSDN 同款的独立工作台：左侧工具、中间所见即所得编辑器、右侧「AI 助手 / 手机预览 / 发布设置」三栏。编辑完成后点「保存渠道稿」，确认无误后点「审核并冻结」。与 CSDN 一样，掘金稿不允许公众号原文链接、文末延伸阅读等软引流内容。

**第三步：两段式发布**

1. 冻结后点击「创建掘金发布任务」：文渡先把任务以“排队”状态保存到本地，再由主进程任务运行器异步通过 `article_draft/create` 创建掘金草稿，正文图片以外部链接方式保留。创建任务后可以先离开当前页面，回来查看任务状态。
2. 草稿创建成功后，任务状态显示「草稿待公开」并展示掘金草稿链接。你可以先点开链接检查标题、正文与图片。
3. 确认无误后点击「确认公开」：文渡调用 `article/publish` 把草稿公开，完成后展示正式文章链接，任务状态变为「已发布」。不确认则不会公开，重复点击也不会产生重复文章。

同一冻结版本只会保留一个可恢复的活动任务；已发布、已取消或结果待核对的任务不会被普通重试覆盖。删除本地渠道稿只会从渠道稿列表隐藏，发布记录和事件仍保留，方便追溯。

**第四步：异常与人工校正**

- 凭据缺失或错误：任务进入「待补凭据」，补齐掘金凭据后可继续。
- 网络失败或公开失败：任务显示失败原因，可在网络恢复后重试。
- 结果不确定（如超时但掘金实际已发布）：任务进入「待人工核对」，你可在掘金后台核实后用「校正状态」把任务标记为已发布、失败或取消，避免重复发布。

## 19. 51CTO 渠道稿（当前可用范围）

51CTO 使用浏览器自动化直发文章，正文中的本地图片会自动上传到 51CTO COS 图床并替换为 CDN 链接，远程图片保持外链。

**第一步：添加 51CTO 账号**

1. 在文渡「账号」中点击添加，选择「51CTO」，填写账号名称并保存。
2. 保存后点击该账号的「配置 51CTO 凭据」，配置 Cookie 一项：
   - **推荐：自动获取 Cookie**：点击「自动获取 Cookie」，文渡会弹出 51CTO 登录窗口（登录为 51CTO 原生流程）。检测到登录成功后，文渡会自动抓取 Cookie 串并回填保存，随后关闭登录窗口；抓取后会用 51CTO 接口自动验证，验证未通过时凭据仍会保存，但界面会提示你检查登录态。
   - 手动配置：登录 51CTO 后从浏览器开发者工具复制请求 Cookie，粘贴到 Cookie 输入框。
3. 凭据由文渡加密保存，不会在界面回显；发布时凭据缺失或错误会进入「待补凭据」状态，可回到账号设置修正。

**第二步：生成并编辑 51CTO 稿**

在「工作台」中打开一篇文章，点击右侧「生成 51CTO 稿」（已归档文章先在「归档库」点 ⋯ 展开后点「重新发布」，在右侧发布设置里选 51CTO 账号，再点「进入 51CTO 渠道稿」）。会打开与 CSDN 同款的独立工作台：左侧工具、中间所见即所得编辑器、右侧「AI 助手 / 手机预览 / 发布设置」三栏。编辑完成后点「保存渠道稿」，确认无误后点「审核并冻结」。

**第三步：填写平台专属参数**

51CTO 渠道稿的发布设置比公众号略多 4 项必填配置：

- **一级栏目 pid**：必选。文渡「加载分类」后一对一抓取自 51CTO 发布页栏目下拉；选项会持久化到本地账号，重复打开时直接复用，无需再次抓取。手动填写只接受 51CTO 后台的纯数字栏目 id。
- **授权分类 cate_id**：必选。**随「一级栏目」联动**——选定一级栏目后只显示该栏目下的二级分类下拉，未选一级栏目时此项可能为空。切换一级栏目会清空已选授权分类，避免错位提交。
- **标签**：必填，多个标签用**英文逗号**分隔，例如 `云计算,后端,Python`。
- **发布形式**：必选。「1 = 原创」「2 = 翻译」「3 = 转载」，下拉单选；如忘记含义可悬停查看。

**「加载分类」工作机制**：点击后文渡会通过账号的 Cookie 拉起一个隐藏 51CTO 发布页窗口，按已登录账号的栏目与分类逐项抓取（一级栏目遍历、二级分类跟随一级栏目级联抓取），抓取完成后关闭窗口、把结果保存到账号本地缓存。失败时显示具体报错，可以直接在上方「一级栏目」「授权分类」输入框手动填写栏目 id / 分类 id 再发布——拉取失败不影响提交。

**第四步：发布**

冻结后点击「发布到 51CTO」：文渡先把任务以“排队”状态保存到本地，再由主进程任务运行器异步通过 51CTO 文章发布接口一步提交，把正文按 51CTO 要求的 HTML 片段格式（包在 am-editor 容器内、`is_old=2`）连同栏目、分类、标签、发布形式一起发送。发布记录会持续显示排队/执行状态；本地图片失败时任务进入失败并提示失败清单，不会降级为 base64 嵌入；任务完成后展示 51CTO 文章链接，状态变为「已发布」。

已发布的稿如果栏目、分类、标签填错想重发：点顶栏「重新发布」复用上次参数直接新建一份任务；如需修改发布参数，先在发布设置里改栏目/分类/标签再点「重新发布」。如发现 51CTO 后台已存在文章但本地显示不一致，可点「校正状态」同步实际状态。

同一冻结版本和发布参数只会保留一个可恢复的活动任务；删除本地渠道稿只会从渠道稿列表隐藏，发布记录和事件仍保留，方便追溯。

## 21. 备份、升级和恢复

- 文章库建议使用 Gitee 私有仓库备份，并在内容变化后提交。
- 文渡数据目录建议每日备份。
- 浏览器登录 Cookie 默认不纳入备份，恢复后重新登录。

## 22. 常见问题

### 为什么文章和数据库中的状态不一致？

正文以 VitePress 文件为准，数据库保存索引和工作流状态。外部修改、回调延迟或已删除文章对应的历史发布记录都可能造成短时差异。重新扫描文章库或在发布记录校正状态，不要直接编辑数据库。

### 为什么检测工具打开了浏览器？

腾讯朱雀和 ContentAny 没有可依赖的稳定官方接口，文渡需要操作网页并读取结果。可见浏览器便于登录、验证码和异常时接管；稳定后可再评估无头模式。

### 为什么微信显示“提交成功”但文章还没发布？

提交成功只表示微信接受了任务。最终状态要等待回调，或由用户在微信后台核实后人工校正。

### 为什么点「校正状态」后记录还在待处理？

「待处理」只显示**尚未确认最终结果**的任务；「发布记录」显示已确认终态的任务（已发布、已取消，以及你在平台后台核实后人工标记为失败的记录）。

发布记录中的微信公众号、CSDN、博客园、掘金和 51CTO 任务均可点击「状态轨迹」查看只读生命周期历史。轨迹按最新事件在前展示任务创建、排队、平台准备、提交、失败、平台回执、人工核对和人工校正等节点；它只用于追溯，不会重新提交平台任务。事件中的状态是跨平台统一的状态，平台专属细节仍以任务卡上的状态说明和远端页面为准。

- 校正弹框的「最终状态」默认**跟随任务当前状态**：失败任务默认就是「发布失败」、取消任务默认「取消发布」、进行中任务默认「已发布」。直接确认即可把记录归档到「发布记录」。
- 把失败任务在后台核实后确认为「发布失败」并确认，记录会从「待处理」移到「发布记录」，并显示红色「已失败」徽标和你填写的核实依据。
- 系统自动判定为失败、但**未经你人工核实**的任务仍留在「待处理」，等待你重试发布或核实后校正；这正是为了避免把未确认的失败误当作已处理。
- 若你不再打算发布这条内容，把「最终状态」选为「取消发布」即可让它进入「发布记录」。

### 双击后没有窗口，或弹出「文渡启动失败」

弹窗里会直接写明失败原因，请先按提示截图反馈。最常见的情况是同一时刻开了两个文渡：本地服务只允许一个实例使用，第二个会启动失败，关掉多余的那个再打开即可。如果窗口一闪就不见了、连提示都没有，请打开「设置 → 数据目录」所示文件夹下的 `logs` 目录，把当天的日志提供给开发者。
