# 领域文档

本文档说明工程技能在本仓库中如何读取领域知识和架构决策。

## 开始探索前

- 先读取根目录的 `CONTEXT.md`。
- 再读取与当前任务相关的 `docs/adr/` 中的 ADR。
- 如果这些文件暂时不存在，继续工作即可，不要把缺失本身当成缺陷，也不要为了满足技能而提前创建空文件。

## 目录结构

本仓库是 single-context 项目：

```text
/
├── CONTEXT.md       # 领域术语、核心概念和稳定约束
├── docs/adr/        # 架构决策记录
└── src/             # 实现代码
```

当领域建模或架构讨论真正产生稳定概念和不可逆决策时，再创建或更新 `CONTEXT.md` 与 ADR；不要提前堆积模板文档。

## 术语约定

涉及领域概念、Issue 标题、重构建议或测试名称时，优先使用 `CONTEXT.md` 中的术语。如果所需概念尚未定义，先记录为领域建模事项，不要在不同文档中创造同义词。

## ADR 冲突

如果新方案与已有 ADR 冲突，必须明确指出冲突的 ADR、冲突原因和是否需要重新讨论，不得静默覆盖原决策。
