# 本地界面验收方法

适用于开发版的用户交互验收。验收员仍须按根目录 `AGENTS.md` 确定目标流程、两个最近的相邻流程和必须运行的检查；涉及生产构建启动路径时，还须执行其中的生产构建启动验证。

## 准备隔离实例

1. 记录 `git status --short`，阅读相关需求、验收标准和交接信息。
2. 在当前执行环境允许写入的位置创建本次专用临时目录，为启动进程设置 `CONTENTFERRY_DEV_USER_DATA_DIR` 与 `CONTENTFERRY_DATA_DIR`。文章库、账号和稿件只用测试数据；核对应用实际使用的数据目录，不接触真实用户资料。不要执行真实平台的发布、删除等写入。
3. 对本地 HTTP API 支持的界面流程，优先使用下节的浏览器方案。需要 Electron 专属能力时，在同一网络与权限边界内启动 `npm run dev`，由它启动 Vite 页面 `http://127.0.0.1:5175`、Electron 和本地服务 `http://127.0.0.1:4317`。如果分别启动进程，先确认它们彼此可访问；不同沙箱或沙箱外进程即使都使用 `127.0.0.1`，也不能假定相互连通。

## 沙箱内浏览器与独立本地服务

本方案已用于项目级 `verifier` 的掘金稿标签界面验收。它适用于浏览器可通过 HTTP API 操作的流程；Electron 子进程无法在 Windows 沙箱中启动时，也可继续验收这些流程。前端使用真实 React 页面，服务端使用真实本地业务实现，仅将明确列出的外部依赖替换为测试夹具。

1. 由父 Agent 准备临时启动入口和测试夹具，放在本次专用临时目录，交接给只负责验证的 `verifier`。当前没有独立的浏览器验收启动命令，须根据当前服务构造接口准备入口，不能假定 `npm run dev:renderer` 会同时启动 API。
2. 使用当前源码执行 `npm run build:main`，再用 `npm run dev:renderer` 启动 `127.0.0.1:5175`。编译前按需执行项目现有的原生模块重建命令。保留各进程输出，启动失败时据此定位。
3. 临时入口以 `ELECTRON_RUN_AS_NODE=1` 运行项目依赖中的 `electron`，使用与 `better-sqlite3` 匹配的 Electron ABI，避免创建桌面窗口。仅在该临时进程内提供服务所需的最小 Electron `app` 适配（如隔离的 `userData`、项目路径和版本），然后加载当前编译产物中的 `buildServer`、数据库及相关业务服务。设置隔离的首次运行配置，使用内存数据库或专用临时数据库，仅监听 `127.0.0.1:4317`。
4. 文章库、账号和稿件均使用虚构测试数据。通过真实本地 API 或仓库现有业务服务准备夹具；外部平台目录、鉴权等依赖按需替换，并列明替代范围。例如掘金标签目录可固定返回 Agent、人工智能、架构、数据库，同时保留真实的渠道稿读取、编辑和保存链路。使用测试凭据，限制外部写操作；不能用模拟保存接口验收实际持久化。
5. 确认页面和 `GET http://127.0.0.1:4317/api/app/settings` 均返回应用响应，再通过当前会话的浏览器工具实际打开 `http://127.0.0.1:5175`。页面加载后继续进入目标稿件，确认编辑器可操作；仅端口连通或接口成功不算界面验收。
6. 向项目级 `verifier` 提供地址、隔离目录、夹具、外部依赖替代范围、日志位置和验收标准。由它实际点击完成目标流程及两个相邻流程，保存后离开并重新打开同一稿件核对状态，逐项报告预期与实际。父 Agent 保持服务运行，收到报告后再关闭。
7. 报告注明浏览器与测试夹具范围。内存数据库中的保存重开只验证同一服务进程内的状态；需要验证应用重启、磁盘持久化或迁移时，使用临时文件数据库并重启服务。preload、IPC、原生对话框、Electron 窗口及生产构建启动须在对应环境另行验证；真实平台行为也须另行验证，未操作的部分标为“未验证”。

## 确认界面可操作

1. 从操作界面所用的执行环境访问 `http://127.0.0.1:5175`，确认页面能加载；同时检查 `127.0.0.1:4317` 可连接且返回应用响应。Electron 窗口已出现但页面显示 `ERR_CONNECTION_TIMED_OUT` 时，先检查 Vite 与 Electron 的执行边界和启动日志，再判断能否验收。
2. 优先使用当前会话实际可用的浏览器工具操作 HTTP 支持的流程；Electron 专属流程使用桌面操作工具。若桌面工具不可用而 Electron 能正常启动，可在隔离的开发版实例上启用仅限本机的 DevTools 调试端口，通过 Chrome DevTools Protocol 检查页面、执行点击和截图；须确认连接的是该实例的页面，不把网络请求或源码推断当成界面操作。调试端口只用于本次验收，结束后关闭。
3. 对外部平台能力，可在隔离实例中使用明确记录的测试夹具验证本地选择、保存、重开等流程；报告须区分测试夹具与真实平台结果。逐项记录操作、预期、实际和截图或日志位置。保存后的状态必须通过重新打开稿件核对。
4. 结束时停止本次启动的进程，复查 `git status --short`。验收员不修改源码、测试、产品文档或用户数据；未能操作的步骤标为“未验证”并写明失败位置。

## 沙箱与审批

先在当前沙箱内启动页面与隔离本地服务，并探测浏览器能否访问它们；需要 Electron 或调试端口的流程再检查对应能力。浏览器方案不以 Electron 桌面窗口启动成功为前提。Windows 沙箱实现与当前网络权限会影响子进程启动和本机端口的可达性；`AGENTS.md` 和本文件不能提升权限或关闭审批。需要在沙箱外启动或向沙箱外终端持续发送输入时，应按当前 Codex 会话的权限设置操作，不把审批弹窗当成应用故障，也不通过关闭安全隔离绕过限制。
