## 使用方式

每项填写“通过 / 不通过 / 不适用 / 待确认”，并记录时间、测试账号、证据链接或截图位置。不得把 AppSecret、Token、Cookie、完整回调请求或用户正文写入本文件或 Git。

### 当前验证结论与安全整改

- 已申请独立测试公众号。通过腾讯 Marvis Agent 已验证 `freepublish/submit` 可调用，以及 `message/mass/sendall` 可将文章群发给测试号的全部关注者。
- 上述结果验证的是微信公众号外部接口能力，不等同于 ContentFerry 已完成接口集成；ContentFerry 的 Token 缓存、草稿映射、回调验签、事件持久化、去重、定时与崩溃恢复仍需在实现后逐项验证。
- 微信已能访问当前开发者 URL；日志中的明文 GET 验证证明入口可达，但不代表真实发布结果事件已经验证。
- 现有验证服务可作为连通性原型，不能直接作为生产回调处理器：真实 POST 事件必须先校验 `msg_signature`，再解密和解析；只有将事件持久化、去重并关联到发布任务后才返回成功。
- 生产服务不得使用调试模式，不得在源码中硬编码回调 Token、EncodingAESKey、AppSecret 或其他凭据。当前测试脚本中的回调 Token 和 EncodingAESKey 应在生产接入前轮换，并迁移到加密配置存储。

## 验收结论

- [ ] 可稳定使用公众号官方接口发布永久链接。
- [ ] 可在账号额度允许时稳定群发通知粉丝。
- [ ] 任何提交都以最终回调/人工核对确认，不以 `errcode=0` 误报成功。
- [ ] 定时、重启恢复和重复回调均不会重复提交。
- [ ] IP 白名单和开发者 URL 回调方案已确定，可支持 Windows 单机交付。

若任一前置项未满足，记录阻塞原因与备选部署方案，再决定是否进入公众号连接器编码。
